# Testing Published Events

|   |   |
|---|---|
||다음 섹션은 Spring 애플리케이션 이벤트 추적에만 집중한 테스트 접근 방식을 설명해요. `@ApplicationModuleListener`를 사용하는 모듈 테스트를 더 전체적으로 다루려면 [[D. Integration Testing Application Modules|Scenario API]]를 확인하면 돼요.|

Spring Modulith의 `@ApplicationModuleTest`는 테스트 메서드에 `PublishedEvents` 인스턴스를 주입받을 수 있게 해요. 이를 사용하면 테스트 중인 비즈니스 작업이 실행되는 동안 특정 이벤트 집합이 발행되었는지 검증할 수 있어요.

애플리케이션 모듈 구조의 이벤트 기반 통합 테스트

- Java

- Kotlin

```java
@ApplicationModuleTest
class OrderIntegrationTests {

  @Test
  void someTestMethod(PublishedEvents events) {

    // …
    var matchingMapped = events.ofType(OrderCompleted.class)
      .matching(OrderCompleted::getOrderId, reference.getId());

    assertThat(matchingMapped).hasSize(1);
  }
}
```

`PublishedEvents`는 특정 조건에 맞는 이벤트를 선택하는 API를 제공해요. 검증은 기대한 개수의 요소가 있는지 확인하는 AssertJ assertion으로 마무리돼요. 어차피 이런 assertion에 AssertJ를 사용한다면, 테스트 메서드 파라미터 타입으로 `AssertablePublishedEvents`를 사용할 수도 있어요. 그러면 Spring Modulith가 제공하는 fluent assertion API를 바로 사용할 수 있어요.

`AssertablePublishedEvents`로 이벤트 발행 검증하기

- Java

- Kotlin

```java
@ApplicationModuleTest
class OrderIntegrationTests {

  @Test
  void someTestMethod(AssertablePublishedEvents events) {

    // …
    assertThat(events)
      .contains(OrderCompleted.class)
      .matching(OrderCompleted::getOrderId, reference.getId());
  }
}
```

`assertThat(…)` 표현식이 반환하는 타입을 보면, 발행된 이벤트에 대한 제약 조건을 직접 정의할 수 있어요. 이 방식은 “이벤트가 발행되었는지”뿐 아니라 “어떤 payload 조건을 만족하는 이벤트가 발행되었는지”까지 테스트에서 명확하게 표현할 수 있게 해요.

다음으로 애플리케이션 모듈 구조 자체의 검증은 [[B. Verifying Application Module Structure]]를 참고하면 돼요.
