# Externalizing Events

|   |   |
|---|---|
||다음 섹션은 비동기 이벤트 리스너에 기반한 Spring Modulith 네이티브 이벤트 외부화를 설명해요. 실용적이고 단순한 해결책이지만, 실제 outbox pattern 구현에서 개발자가 기대할 수 있는 중요한 기능은 부족해요. Spring Modulith 2.1은 [[Namastack Outbox]]와 [[JobRunr]]를 통한 이벤트 외부화 지원을 도입했어요. 자세한 내용은 이 문서의 [[4. Externalizing Events#Namastack Outbox Support|Namastack]] 및 [[4. Externalizing Events#JobRunr Outbox Support|JobRunr]] 섹션을 참고하면 돼요.|

애플리케이션 모듈 사이에서 주고받는 이벤트 중 일부는 외부 시스템에도 중요할 수 있어요. Spring Modulith는 선택한 이벤트를 다양한 메시지 브로커로 발행할 수 있게 해요. 이 지원을 사용하려면 다음 단계를 따르면 돼요.

1. 프로젝트에 브로커별 Spring Modulith 아티팩트를 추가해요.
2. 외부화할 이벤트 타입을 Spring Modulith 또는 jMolecules의 `@Externalized` 애노테이션으로 표시해요.
3. 애노테이션 값에 브로커별 라우팅 대상을 지정해요.

이벤트 외부화 대상을 선택하는 다른 방법이나 브로커 내 라우팅 커스터마이징 방법은 [[4. Externalizing Events#Fundamentals of Event Externalization|Event Externalization 기본 원리]]를 참고하면 돼요.

## Supported Infrastructure

|Broker|Artifact|Description|
|---|---|---|
|Kafka|`spring-modulith-events-kafka`|브로커와의 상호작용에 Spring Kafka를 사용해요. 논리 라우팅 키는 Kafka topic과 message key로 사용돼요.|
|AMQP|`spring-modulith-events-amqp`|호환되는 브로커와의 상호작용에 Spring AMQP를 사용해요. 예를 들어 Spring Rabbit에 대한 명시적 의존성 선언이 필요해요. 논리 라우팅 키는 AMQP routing key로 사용돼요.|
|JMS|`spring-modulith-events-jms`|Spring의 핵심 JMS 지원을 사용해요. 라우팅 키는 지원하지 않아요.|
|Spring Messaging|`spring-modulith-events-messaging`|Spring의 핵심 `Message`와 `MessageChannel` 지원을 사용해요. `Externalized` 애노테이션의 `target`에 지정된 Bean 이름으로 대상 `MessageChannel`을 찾고, 라우팅 정보를 `springModulith_routingTarget`이라는 header로 전달해요. 이 header는 보통 Spring Integration의 `IntegrationFlow` 같은 downstream 컴포넌트에서 처리돼요.|

## Fundamentals of Event Externalization

Spring Modulith의 이벤트 외부화는 [[2. Application Module Listener|트랜잭션 이벤트 리스너]]가 브로커별 발행 구현에 위임하는 방식으로 구현돼요. 따라서 Spring Modulith의 [[3. Event Publication Registry]]가 브로커와의 상호작용 중 발생하는 실패로부터 외부화를 보호해요. 실패한 발행은 제공되는 API를 통해 다시 제출할 수 있어요.

이벤트 외부화는 발행된 각 애플리케이션 이벤트에 대해 세 단계를 수행해요.

1. 이벤트가 외부화 대상인지 결정해요. 이를 event selection이라고 불러요. 기본적으로 Spring Boot 자동 구성 패키지 안에 있고 지원되는 `@Externalized` 애노테이션 중 하나가 붙은 이벤트 타입만 외부화 대상으로 선택돼요.
2. 메시지를 준비해요. 이 단계는 선택 사항이에요. 기본적으로 이벤트는 해당 브로커 인프라에 의해 있는 그대로 직렬화돼요. 선택적인 mapping 단계로 개발자는 원래 이벤트를 외부 당사자에게 적합한 payload로 커스터마이즈하거나 완전히 대체할 수 있어요. Kafka와 AMQP의 경우 발행할 메시지에 header도 추가할 수 있어요.
3. 라우팅 대상을 결정해요. 메시지 브로커 클라이언트는 메시지를 발행할 논리 대상을 필요로 해요. 이 대상은 보통 브로커에 따라 topic, exchange, queue 같은 물리 인프라를 식별하고, 이벤트 타입에서 정적으로 파생되는 경우가 많아요. `@Externalized` 애노테이션에 명시적으로 정의하지 않으면, Spring Modulith는 애플리케이션 로컬 타입 이름을 대상으로 사용해요. 예를 들어 base package가 `com.acme.app`인 Spring Boot 애플리케이션에서 이벤트 타입 `com.acme.app.sample.SampleEvent`는 `sample.SampleEvent`로 발행돼요.

일부 브로커는 실제 대상 안에서 서로 다른 목적으로 쓰이는 더 동적인 routing key도 허용해요. 기본적으로는 routing key를 사용하지 않아요.

## Annotation-based Event Externalization Configuration

`@Externalized` 애노테이션으로 커스텀 라우팅 키를 정의하려면 `$target::$key` 패턴을 사용할 수 있어요. 이 패턴은 각 애노테이션에서 사용할 수 있는 target 또는 value 속성에 들어가요. target과 key는 모두 SpEL 표현식이 될 수 있고, 이벤트 인스턴스가 root object로 설정돼요.

SpEL 표현식으로 동적 라우팅 키 정의하기

- Java

- Kotlin

```java
@Externalized("customer-created::#{#this.getLastname()}") 
class CustomerCreated {

  String getLastname() { 
    // …
  }
}
```

`CustomerCreated` 이벤트는 accessor 메서드로 고객의 성을 노출해요. target 선언의 `::` 구분자 뒤에 있는 key 표현식에서 `#this.getLastname()` 표현식으로 그 메서드를 사용해요.

키 계산이 더 복잡해진다면 이벤트를 인자로 받는 Spring Bean으로 위임하는 편이 좋아요.

라우팅 키 계산을 Spring Bean에 위임하기

- Java

- Kotlin

```java
@Externalized("…::#{@beanName.someMethod(#this)}")
```

## Programmatic Event Externalization Configuration

`spring-modulith-events-api` 아티팩트에는 위에서 언급한 모든 단계를 개발자가 커스터마이즈할 수 있게 해주는 `EventExternalizationConfiguration`이 들어 있어요.

이벤트 외부화를 프로그래밍 방식으로 설정하기

- Java

- Kotlin

```java
@Configuration
class ExternalizationConfiguration {

  @Bean
  EventExternalizationConfiguration eventExternalizationConfiguration() {

    return EventExternalizationConfiguration.externalizing()                 
      .select(EventExternalizationConfiguration.annotatedAsExternalized())   
      .mapping(SomeEvent.class, event -> …)                                  
      .headers(event -> …)                                                   
      .routeKey(WithKeyProperty.class, WithKeyProperty::getKey)              
      .build();
  }
}
```

|   |   |
|---|---|
||먼저 `EventExternalizationConfiguration`의 기본 인스턴스를 만들어요.|
||이전 호출에서 반환된 `Selector` 인스턴스의 `select(…)` 메서드 중 하나를 호출해 이벤트 선택 방식을 커스터마이즈해요. 이 단계는 애플리케이션 base package 필터를 근본적으로 비활성화해요. 이제 애노테이션만 보기 때문이에요. 타입 기준, 패키지 기준, 패키지와 애노테이션 기준으로 이벤트를 쉽게 선택하는 convenience method가 있어요. 선택과 라우팅을 한 번에 정의하는 shortcut도 있어요.|
||`SomeEvent` 인스턴스에 대한 mapping 단계를 정의해요. 추가로 router에서 `….routeMapped()`를 호출하지 않는 한, 라우팅은 여전히 원래 이벤트 인스턴스를 기준으로 결정된다는 점에 주의해야 해요.|
||보낼 메시지에 커스텀 header를 추가해요. 예제처럼 일반적으로 추가할 수도 있고, 특정 payload 타입에 대해서만 추가할 수도 있어요.|
||마지막으로 이벤트 인스턴스에서 값을 추출하는 method handle을 정의해 routing key를 결정해요. 또는 이전 호출에서 반환된 `Router` 인스턴스의 일반적인 `route(…)` 메서드를 사용해 개별 이벤트에 대해 전체 `RoutingKey`를 만들 수도 있어요.|

## Serializing Event Externalization

Spring Modulith의 이벤트 외부화는 트랜잭션 이벤트 리스너로 구현돼요. 즉 여러 thread가 동시에 브로커와의 상호작용을 트리거할 수 있어요. 특히 이벤트 발행이 다시 제출될 때 이 점이 중요해질 수 있어요. 브로커 입장에서는 갑자기 상호작용이 급증할 수 있고, 일부 상호작용은 시간이 더 걸릴 수 있어요. 그 결과 나중 이벤트의 외부화가 이전 이벤트를 앞지를 수 있어요.

이를 막으려면 `spring.modulith.events.externalization.serialize-externalization` 속성을 `true`로 설정해 브로커와의 상호작용을 직렬화할 수 있어요. 그러면 한 번에 하나의 이벤트만 전송돼요.

## Namastack Outbox Support

고급 outbox 기능이 필요하다면 이벤트 외부화를 [[Namastack Outbox]]로 위임할 수 있어요. 이 기능은 현재 관계형 데이터베이스에서만 사용할 수 있어요. 기능을 활성화하려면 먼저 Spring Modulith Namastack starter를 프로젝트에 추가해요.

Spring Modulith Namastack starter 선언하기

- Maven

- Gradle

```none
dependencies {
  implementation 'org.springframework.modulith:spring-modulith-starter-namastack'
}
```

이벤트 외부화를 자동으로 Namastack에 위임하려면 `spring.modulith.events.externalization.mode` 속성을 `outbox`로 바꿔요. Namastack Outbox의 일반적인 동작을 커스터마이즈하는 방법은 Namastack [[Namastack Outbox|reference documentation]]을 참고하면 돼요. GitHub 저장소의 [[Spring Modulith Outbox Example|예제]]도 확인할 수 있어요.

## JobRunr Outbox Support

이벤트 외부화를 위한 [[4. Externalizing Events#Namastack Outbox Support|Namastack 지원]]과 비슷하게, Spring Modulith는 [[JobRunr]] 지원도 제공해요. 기능을 활성화하려면 먼저 Spring Modulith JobRunr starter를 프로젝트에 추가해요.

Spring Modulith JobRunr starter 선언하기

- Maven

- Gradle

```none
dependencies {
  implementation 'org.springframework.modulith:spring-modulith-starter-jobrunr'
}
```

이벤트 외부화를 자동으로 JobRunr에 위임하려면 `spring.modulith.events.externalization.mode` 속성을 `outbox`로 바꿔요. JobRunr 사용 방법에 대한 자세한 내용은 [[JobRunr Reference Documentation|reference documentation]]을 참고하면 돼요. GitHub 저장소의 [[Spring Modulith Outbox Example|예제]]도 확인할 수 있어요.
